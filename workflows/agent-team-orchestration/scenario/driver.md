# Agent 团队编排审查规则

运行时应逐步检查产物是否满足以下契约，并只针对当前步骤缺失的内容提出修正意见。

## define_scope

确认 `scope_brief` 同时覆盖目标、范围、不做事项、输入、交付物、约束、风险和待确认假设，
且没有虚构已经完成的工作。

## design_team

确认 `team_blueprint` 使用最小充分团队，每个 Agent 只有一个主要角色，每项产物有唯一负责人，
并清楚区分并行任务和串行依赖。

## define_handoffs

确认 `handoff_protocol` 包含完整状态生命周期、状态所有权、共享产物约定、阻塞上报和五项交接
字段：完成内容、产物位置、验证方式、已知问题、下一动作。

## design_quality_gates

确认 `quality_plan` 保持构建与批准职责分离，并对超时、能力不匹配、依赖失败、产物缺失和审查
不通过给出明确的升级或恢复动作。

## assemble_plan

确认 `orchestration_plan` 与所有前序产物一致，能够直接用于分派和验收，且明确最终负责人、停止
条件和启动前仍需确认的假设。
