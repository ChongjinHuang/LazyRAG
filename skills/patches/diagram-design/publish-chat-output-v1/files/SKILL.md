# Diagram Design

Create a clear diagram as self-contained HTML with inline SVG and CSS. Preserve the user's facts; ask once for missing information that changes essential nodes, order or branches. Mark reasonable assumptions beside the diagram. Do not read the whole package.

## Resolve style and select a type

1. Before every diagram, call the workspace directory-listing tool for `.`. Use its returned absolute project path with `run_skill_script(name="diagram-design", rel_path="scripts/resolve_style.py", args=["--project-root", "<absolute-project-root>"])`. This read-only resolver checks `.diagram-design` first, validates the selected profile and returns only effective colors/fonts. Do not read the full profile-management or style-guide documents after a successful result. Report warnings; a missing/invalid profile structure requires resolution with the user, never a silent fallback. If script execution is unavailable, follow only the generation-resolution sections of `references/profiles.md` and read the selected guide directly. Do not copy a marker-selected profile over the working guide. Use `references/profiles.md` for explicit profile management, and `references/onboarding.md` for requested brand customization. With no marker and pristine defaults, proceed without a brand questionnaire.
2. Read `references/core-rules.md` and the selected type reference. Common routes: decision/approval paths → `references/type-flowchart.md`; time-ordered messages → `references/type-sequence.md`; components/connections → `references/type-architecture.md`; role handoffs → `references/type-swimlane.md`. For other or ambiguous needs, read `references/type-index.md`, which retains all 39 type routes and use boundaries. If behavior, state, enforcement or risk carries the meaning, select a semantic pattern using `references/semantic-patterns.md` before choosing layout. Read `references/type-budgets.md` only for a type with a specialized budget or when near its limit.
3. Briefly state the type/pattern, size and planned cuts; allow redirection when these are uncertain. Proceed directly when already specified, or note assumptions if the user is unavailable. Use `references/presentation.md` for summary cards, dark/full/consultant/sketchy/terminal variants and template selection; read animation/icon/annotation references only when those features are needed. For multi-series, terminal or CJK token detail, rerun the style resolver with the corresponding `--details series`, `--details terminal` or `--details cjk` option rather than reading unrelated style sections. The default is minimal light, static, using `assets/template.html` when a starting file is useful. Examples are optional; do not load them just to confirm the default.

## Draw, validate and deliver

- Use `references/svg-primitives.md` only when code examples or detailed connector construction are needed; `references/design-details.md` preserves the complete upstream design/output checks for questions the compact rules do not answer.
- For existing draw.io or Mermaid sources, read `references/import-guide.md` then the matching import reference. `scripts/mermaid_extract.py <existing-file>` and `scripts/drawio_extract.py <existing-file>` parse sources for redrawing; they are not generators and do not accept node/title/output-format arguments. For prose requirements, author the HTML directly. Export PNG/SVG only when requested, per `references/export.md`.
- In LazyMind, first call `run_skill_script(name="diagram-design", rel_path="scripts/prepare_html.py", args=["--output", "<absolute-project-root>/<filename>.html", "--html", "<complete HTML>"])`. This helper runs the unchanged `self_check.py` before atomically writing the workspace file. On failure, repair the HTML and retry the helper; nothing has been published. Check the selected type and core gate too: self-check does not prove all geometry/taste rules. If using ordinary filesystem tools instead, write and run `scripts/self_check.py <absolute-html-path>` before publication.
- Only after a successful check, call `save_chat_artifact(filename="<filename>.html", content="<validated absolute path>", content_type="file")` once. The content type is exactly `file`, never `html`, `image` or a MIME type. Do not use the save tool to create the file for checking; that would publish an unchecked version. If script/filesystem tools are unavailable, disclose the limitation and provide HTML source without claiming a validated artifact. A workspace file alone is not delivery. Copy each returned `file_markdown` link verbatim into a short final reply and finish; do not add optional refinements after delivery.
